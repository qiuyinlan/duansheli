# 接入 Supabase：让电脑和手机同步

这份文档是**照着做就能通**的步骤清单。全程大约 15 分钟，
需要你动手的地方只有「点几下网页」和「填两个值、重新构建」。
代码部分已经写好了（`src/cloud/`），你不需要改任何代码。

---

## 0. 先搞清楚它到底怎么工作（30 秒）

```
   电脑                                   手机
┌─────────────┐                       ┌─────────────┐
│  应用界面    │                       │  应用界面    │
│  IndexedDB  │ ← 主副本，断网照常用 →│  IndexedDB  │
└──────┬──────┘                       └──────┬──────┘
       │  合并（只做加法 + 删除墓碑）          │
       └──────────┬──────────────┬───────────┘
                  ▼              ▼
            ┌─────────────────────────┐
            │  Supabase（你的项目）     │
            │  app_data 表：一账号一行  │
            └─────────────────────────┘
```

三条要记住的性质：

1. **本地 IndexedDB 仍然是主副本。** 断网、退出登录、Supabase 挂了 —— 应用照常用，
   数据照常存在这台设备上。云端只是「另一台设备的副本」。
2. **每次同步 = 拉远端 → 和本地合并 → 落回本地 → 再把结果推上去。**
   合并用的是导入备份那套算法（id 去重、`updatedAt` 较新者胜、
   位置分类按名称路径对齐），外加**删除墓碑** —— 没有墓碑的话，
   你在电脑上删掉的东西会被手机原样加回来。
3. **冲突不会静默丢数据。** 推的时候如果另一台设备写过了，会先合并再重推；
   合并只做加法，两边的东西都会留下。

## 1. 建 Supabase 项目

1. 打开 <https://supabase.com>，用 GitHub 或邮箱注册（免费档就够 —— 你的数据约 60KB，
   免费档有 500MB 数据库和 5GB 流量）。
2. 右上角 **New project**：
   - **Name**：随便，比如 `duansheli`
   - **Database Password**：随便生成一个，**这个密码跟同步功能无关**，记不记都行
     （数据库是 Supabase 自己连的，我们只用它的 REST 接口，永远不直连 Postgres）
   - **Region**：选离你近的，比如 `Northeast Asia (Tokyo)` 或 `Southeast Asia (Singapore)`
3. 等 1~2 分钟，项目状态变成绿色 `Active`。

> ⚠️ **免费档有个坑**：项目**连续 7 天没有任何请求**会被自动暂停（pause）。
> 平时你天天用就不会触发；真被暂停了，去控制台点一下 `Restore` 就能恢复，数据不丢。
> 不放心的话，隔几天在手机上打开一次应用（会自动同步一次）就够了。

## 2. 建表 + 开访问规则

1. 左侧栏 → **SQL Editor** → **New query**。
2. 打开仓库里的 `supabase/schema.sql`，**整份复制**粘进去。
3. 点 **Run**（或 Ctrl+Enter）。应该显示 `Success. No rows returned`。

这一步做了三件事：

| 做了什么 | 为什么非做不可 |
|---|---|
| 建 `app_data` 表（`user_id` / `doc` / `rev` / `device_id` / `updated_at`） | 一个账号一行，`doc` 里装整份数据 |
| 打开 **RLS** 并建四条策略（`auth.uid() = user_id`） | **安全底线**。anon key 是公开的（它会打进网页 JS），没有 RLS 的话任何人拿到就能读全库 |
| 把权限只给 `authenticated` 角色，`anon` 一个都不给 | 未登录的人连表都读不到 |

验证一下（可选）：SQL Editor 里跑

```sql
select relname, relrowsecurity from pg_class where relname = 'app_data';
```

`rowsecurity` 必须是 `true`。**如果是 false，先去把脚本重跑一遍** —— 这时候同步能通，
但你的数据对全世界都是可读的。

## 3. 打开邮箱登录

1. 左侧栏 → **Authentication** → **Providers** → 找到 **Email**，确认它是 **Enabled**。
2. 关于 **Confirm email**（同一个页面里）：
   - **保持打开（推荐）**：注册后要去邮箱点一下确认链接才能登录。安全。
     **只需要确认一次** —— 手机和电脑登录同一个账号，不会各要一次。
   - 想更省事就关掉：注册完直接能登录（少一步、少一个「邮件怎么没收到」的坑）。
   - 如果你怎么都收不到确认邮件：多半是 Supabase 自带的免费发信服务
     **每小时只有 2~3 封**的限额（而且可能直接进垃圾箱）。
     个人自用的话，直接把它关掉最省事。
3. **注册完自己的账号之后，建议把注册关掉**（`Authentication` → `Sign In / Providers` →
   Email 里的 **Allow new users to sign up** 关掉）。
   理由：这个项目的网址是公开的，anon key 也在网页里；注册开着的话
   任何人都能自己注册一个账号来占用你的项目配额（**看不到你的数据** —— RLS 挡着，
   但会白占存储和流量）。你自己那个已存在的账号不受影响。

## 4. 拿到 URL 和 Publishable key

左侧栏 → **Project Settings**（齿轮）→ **API Keys**：

| 页面上叫什么 | 填到哪里 |
|---|---|
| **Project URL**（`https://xxxx.supabase.co`） | `VITE_SUPABASE_URL` |
| **Publishable key**（`sb_publishable_...`） | `VITE_SUPABASE_ANON_KEY` |

> ⚠️ **取名换过一轮，这里最容易拿错**（很多教程还是旧写法）：
>
> | 新界面 | 老界面 | 能不能放进前端 |
> |---|---|---|
> | **Publishable key** `sb_publishable_...` | `anon` / `public`（`eyJ...` 开头） | ✅ **就是这把** |
> | **Secret key** `sb_secret_...` | `service_role`（`eyJ...` 开头） | 🚫 **绝对不能** |
>
> 两行说的是同一种角色，只是改了名字 —— **Publishable key 就是 anon key**，
> 不需要再去别处找那个 `eyJ...` 开头的老格式（老的也还能用，两种都行）。
> 变量名之所以还叫 `..._ANON_KEY`，是为了兼容旧配置，不是让你去找 anon。

> 🚫 **Secret key / service_role 能绕过 RLS 读全库**，而前端代码是人人可见的
> （它会被打进网页 JS）—— 填进去等于把整个数据库的钥匙挂在网页上。
> 程序会主动认这两种钥匙并**拒绝启动云端功能**，设置页上会告诉你该怎么补救。
> 万一你已经把页面部署出去过，补救动作只有一个：去控制台**撤销那把钥匙并重发**。

## 5. 本地开发怎么配

在项目根目录新建 `.env.local`（可以照抄 `.env.example`）：

```ini
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_xxxxxxxxxxxxxxxxxxxx
```

> ⚠️ **两个容易踩的坑**
> 1. **必须重启开发服务器。** 环境变量是 Vite 在**启动时**读进 `import.meta.env` 的，
>    热更新不会重新读。改完 `.env.local` 一定要停掉 `npm run dev` 再起来。
> 2. **Windows 上别用记事本建这个文件**：它很容易变成 `.env.local.txt`，
>    而资源管理器默认隐藏扩展名，你看不出来。
>    用 PowerShell：`notepad .env.local`（在项目目录里执行）。

然后：

```bash
npm run dev
```

打开应用 → **设置 → 云端同步** → 输入邮箱密码 → **注册** → 去邮箱点确认链接（如果开着确认）
→ 回来 **登录** → 看到「已同步」就成了。

> **如果设置页上没有登录表单**，那说明配置还没生效（登录表单故意只在配好之后才出现——
> 给你一个填了也连不上的登录框更糟）。对着这几条查：
> - `.env.local` 的文件名对不对（不是 `.env.local.txt`）
> - 两个变量名是不是 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`（`VITE_` 前缀不能少）
> - **开发服务器重启过没有**
> - 是不是填的还是 `.env.example` 里的 `xxxx`（程序会认出来并提示你）

> `.env.local` 已经在 `.gitignore` 里，不会被提交。
> 变量只有 `VITE_` 开头的才会被 Vite 暴露给前端 —— 这一点别改，
> 它是「哪些值可以被公开」的一条明确边界。

## 6. 线上部署（手机要用的话，这一步必须做）

手机要能打开这个应用，它得有个网址。这个仓库已经配好了 GitHub Pages 部署
（`.github/workflows/deploy.yml`），你只需要把两个值交给它：

1. GitHub 仓库 → **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret**，建两个（名字必须一模一样）：
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. 回到 **Actions** 页 → 选「部署到 GitHub Pages」→ **Run workflow**（或者随便推一次代码）

构建时这两个值会被打进产物里，所以**换了 Supabase 项目要重新部署一次**，
不是改了就生效。

然后：

- 电脑打开 `https://<你的用户名>.github.io/duansheli/`
- 手机用同一个网址打开 → 浏览器菜单里「添加到主屏幕」→ 变成一个 App（这就是 PWA）
- 手机上也登录同一个邮箱 → 两边开始互相同步

> ⚠️ **浏览器数据是按网址隔离的**，这一点很要紧：
> `localhost`、局域网 IP、GitHub Pages 是**三个互不相通的本地仓库**。
> 云端同步会把它们连起来，但第一次在各地址登录时，应用会问你
> **「云端已经有数据了，用哪边？」** —— 那就是这个机制在起作用，选之前看清楚。
> 设置页的「存储状态」里也一直写着当前网址，方便你分辨自己在哪个仓库里。

## 7. 第一次同步会问你一个问题

当你**在云端已经有数据**、而这台设备上**也有数据**时，应用会停下来让你选（不会自己决定）：

| 选项 | 会发生什么 | 什么时候选它 |
|---|---|---|
| **合并（推荐）** | 两边求并集，同一个 id 取改动时间较新的那份 | 不确定就选这个。**唯一不会直接丢数据的选项** |
| 用这台设备的覆盖云端 | 云端那份被整份替换 | 云端是你在另一台设备上误录的废数据 |
| 用云端的覆盖这台设备 | 本机这份被整份替换 | 这台设备（比如新手机）上还是空的脚手架 |

合并的代价要提前知道：**分类和位置可能各留一份**。
两台设备各自建的分类 id 不同，名字一样也不会自动认成同一个
（按名称路径对齐只在「导入备份」那条路里做）。选完合并之后，
去「分类」页把重复的归拢一下就好 —— 物品不会丢。

## 8. 怎么确认它真的在同步

设置页 → 云端同步，那几行就是全部状态：

| 显示 | 意思 |
|---|---|
| 已同步 | 上一次同步成功，没有待推的改动 |
| 同步中… | 正在跑 |
| 有改动待同步 | 本地改过了，正在等（改完约 2.5 秒后自动推） |
| 同步失败 / 需要更新程序 | 看下面那条提示，里面有原因；点「立即同步」重试 |
| 这台设备 `xxxxxxxx` | 这台设备的编号。两台设备编号不同是正常的 |

**它会自己同步的时机**：启动后、每次改完（延迟 2.5 秒）、切回前台、网络恢复、点「立即同步」。

想确认的话，最直接的办法是：**在电脑上录一件东西 → 手机上切回应用 → 应该能看到它**。
（反之亦然。）没看到就点一下「立即同步」。

## 9. 遇到问题怎么办

| 现象 | 原因 / 怎么办 |
|---|---|
| 设置页说「还没配置云端」 | 环境变量的名字不对、文件没生效、或者**没重启开发服务器**。见第 5 步那两条坑 |
| 设置页说「危险：你填的是 Secret key」 | **立刻去控制台撤销那把钥匙并重发一把**（`API Keys` → Secret keys → Revoke）。前端只能用 Publishable key；如果你已经部署过页面，那把钥匙就等于公开了 |
| 设置页说「看起来还是 .env.example 里的示例值」 | 把 `xxxx` 换成你自己项目的真值，重启 |
| 「云端还没建表」 | 第 2 步的 SQL 没跑，或者跑在了另一个项目上 |
| 「邮箱或密码不对」 | 就真的是错的。忘了密码去 Supabase → Authentication → Users 里重置 |
| 「这个邮箱还没确认」 | 去邮箱点确认链接（也看看垃圾箱）。或者按第 3 步把 Confirm email 关掉 |
| 「连不上云端」 | 网络问题。**本地数据不受影响**，联网后会自动再同步 |
| 一直「同步中…」 | 网络慢或卡住了。切一下前台、或者点「立即同步」；数据在本地，急不来也不丢 |
| 同步完东西变少了 | 那是**另一台设备上删掉的**，应用会弹一条「另一台设备删掉了 N 项」。想找回来的话，去设置页回退快照（快照是每台设备各自的） |
| 手机上一直看不到电脑的数据 | 先点「立即同步」；还不行就确认两台设备登录的是**同一个邮箱**；注意不同网址（localhost / Pages）是各自独立的登录状态 |
| 想看看原始报错 | 错误提示下面有「展开技术细节」，那里是 Supabase 返回的原文 |

## 10. 想关掉 / 换项目

- **关掉**：把 `.env.local` 里的两个变量删掉（或清空）重启即可。已经同步过的数据还在本机，
  云端那份也还在（不会自动删）。
- **换项目**：改两个环境变量 → 重新构建/部署。**新项目里要再跑一遍 `supabase/schema.sql`。**
  换项目之后相当于换了一个云端，第一次同步会重新问你「用哪边」。
- **不想再要云端的数据**：去 Supabase 控制台 → Table Editor → `app_data` → 删掉那一行；
  或者 SQL Editor 里 `delete from app_data;`（RLS 保证你只会删到自己的）。

## 附：这套东西在代码里的位置

想读代码或者改行为，看这几个文件就够：

| 文件 | 管什么 |
|---|---|
| `supabase/schema.sql` | 数据库那边的一切（表 + RLS + 权限） |
| `src/cloud/envelope.ts` | **数据格式与合并规则**，全是纯函数：信封、删除墓碑、内容比对。最需要看懂的一个文件 |
| `src/cloud/sync.ts` | 同步引擎：什么时候同步、拉-合-推的顺序、登录/退出、首次绑定的三种选择 |
| `src/cloud/client.ts` | 怎么连上 Supabase（读环境变量、懒创建客户端） |
| `src/components/CloudSyncPanel.tsx` | 设置页那块界面 |
| `src/store/useAppStore.ts` 的 `applySyncedData` | 同步结果怎么落地（**业务代码唯一被改动的地方**） |
| `tests/cloud.ts` / `tests/cloudEngine.ts` | 这些规矩的测试：合并只做加法、删除传得过去、两台设备收敛、冲突要先合并 |

几条**改代码时别踩的坑**（都写在各自的注释里了）：

1. **不许**给 `AppData` 加同步专用字段 —— 它还要原样导出、原样导入。
   墓碑、设备号都放在信封里 / IndexedDB 的 kv 表里。
2. **不许**在比较内容时用 `JSON.stringify` —— Postgres 的 `jsonb` 会重排键的顺序，
   比出来永远「不相等」，会让两台设备互相推个没完。用 `canonical()` / `sameContent()`。
3. **不许**去掉墓碑 —— 去掉之后「在电脑上删掉的东西」会在手机上复活。
4. 冲突时**不许**无条件覆盖 —— 那正是「手机上刚录的东西被电脑整份盖掉」。
5. 墓碑是按**账号**分开放的（`cloud:tombstones:<userId>`）。
   共用一个键会让换账号时的删除记录串到新账号上，那是不可恢复的删数据。
