# 断舍离 · 个人物品整理

> 录入你的所有物品，给它们指定位置，按分类随时回看。
> 目标只有一个：**让你看清自己到底有多少东西，然后扔掉该扔的。**

电脑和手机都能用，每个板块有自己的主色，数据只存在你自己的设备上。

## 怎么跑起来

需要 **Node 18 或更高版本**（推荐 20+）。

```bash
npm install     # 安装依赖
npm run dev     # 启动开发服务器，打开提示的地址即可
```

其他命令：

```bash
npm run build      # 类型检查 + 打包到 dist/
npm run preview    # 本地预览打包结果
npm test           # 运行测试（408 项）
npm run typecheck  # 只做类型检查
npm run audit:i18n # 检查有没有漏翻的中文、两份词典是否对齐
npm run check      # 上面三样一起跑（提交前跑这个）
npm run icons      # 重新生成 PWA 图标
```

还附带一个诊断脚本，用来确认 DeepSeek 是否仍允许浏览器直连（AI 功能的安全前提）：

```bash
node scripts/probe-deepseek-cors.mjs
```

首次打开时，程序会给你铺一套**起步脚手架**：常用的 10 个分类、一套居家位置树
（家 › 卧室 › 衣柜…）、5 个属性定义、3 个常用标签。**不会塞任何示例物品**，
物品列表从空开始。这些脚手架都可以随意改名或删除。

## 部署到 GitHub Pages

推送代码就会自动部署，全程免费。

### 一次性配置

1. 在 GitHub 上新建一个仓库（**Public** 或 Private 都行，Pages 对公共仓库免费），
   不要勾选 "Add a README"。
2. 在项目目录里把代码推上去：

   ```bash
   git init
   git add .
   git commit -m "断舍离 v1"
   git branch -M main
   git remote add origin https://github.com/你的用户名/你的仓库名.git
   git push -u origin main
   ```

3. 打开仓库的 **Settings → Pages**，把 **Source** 改成 **GitHub Actions**。
4. 回到 **Actions** 标签页，等待「部署到 GitHub Pages」跑完（约 1～2 分钟）。

### 访问地址

```
https://你的用户名.github.io/你的仓库名/
```

手机浏览器打开这个地址后，可以「添加到主屏幕」，之后就像 App 一样打开，还能离线使用。

> 部署配置里已经用了相对路径（`base: './'`）和 Hash 路由，
> 所以**仓库名随便叫什么都能跑**，刷新页面也不会 404。

## 数据安全（请务必读这一段）

这一版是**纯本地**的：数据存在你自己浏览器的 IndexedDB 里，**不会上传到任何服务器**。
私密、免费、不依赖网络，但也带来三个必须知道的事实。

### 1. 手机和电脑是两份独立数据，不会自动同步

GitHub Pages 只是把网页文件发给你，它不存你的数据。
在电脑上打开，数据落在电脑浏览器里；在手机上打开，数据落在手机浏览器里，两边互相看不见。

要搬家就用导出 / 导入：

```
手机：设置 → 导出 JSON → 通过微信 / 网盘 / 邮件传到电脑
电脑：设置 → 导入备份 → 选择「覆盖」 → 完成
```

想把两边各自录的东西合起来，导入时选「**合并**」——位置会按名称路径自动对齐，
缺失的会自动补建，导入结束后会给你一份详细报告。

### 2. 浏览器数据可能被清掉
清理浏览器数据、换浏览器、无痕模式、iOS 长期不访问都可能让数据消失。
**所以请定期导出 JSON 备份**，存到网盘或电脑里。

程序里做了这几层保护：

| 机制 | 作用 |
|---|---|
| **自动快照** | 每次修改前自动存一份（同一分钟只留一份），最多 30 份；导入前、删除位置/分类/属性前的快照额外保底保留 |
| **一键导出** | 设置页导出完整 JSON；超过 7 天没导出，概览页会温和提醒 |
| **导入前自动备份** | 导入永远可回退；回退前又会再存一份，所以**回退本身也能回退** |
| **已舍弃回收站** | 扔掉的东西不真删，留在回收站里可以回顾也能恢复 |
| **写不进去时会挂横幅** | 见下面「保存失败怎么办」 |

#### 保存失败怎么办

有时会看到这句：

```
保存到本地失败：Failed to execute 'transaction' on 'IDBDatabase':
The database connection is closing.
```

**这不代表数据坏了。** 它的意思是：浏览器把数据库连接关掉了 ——
另一个标签页、清了站点数据、浏览器回收存储空间，都会这样，
是**浏览器的正常行为**，不是 bug。

程序现在会**自己重开连接、把这次写入完成**，所以正常情况你根本不会看到它。
万一还是失败了（重试也没成功），界面顶上会**一直挂着**一条横幅：

```
⚠️ 这次改动没能存进本地：<原因>。……
   你现在看到的内容还在内存里，但一刷新就会丢。
                              [重试保存]  [先导出备份]
```

两条出路，按严重程度选：

1. **先点「重试保存」** —— 多数情况一下就好了
2. **还不行就点「先导出备份」** —— 把现在（内存里）这份完整导成 JSON 带走，
   然后刷新页面、再导入回来。**这是数据不丢的最后一条路**

> 横幅**不会自己消失**，这是刻意的：保存失败是唯一一种
> 「界面看起来完全正常、实际没存进去」的情况，不能让你三秒之后就忘了。

### 3. 换域名会让旧数据「看不见」

浏览器的存储按域名隔离。如果你以后给 GitHub Pages 绑了自定义域名，
域名一变，旧域名下的数据就不会跟过来（数据还在，只是换了把钥匙）。

**绑定自定义域名之前，务必先导出 JSON。**

### 4. 换**网址**也一样（这条特别容易踩）

不只是换域名 —— **同一个项目的不同访问地址之间，数据也是完全隔离的**：

| 地址 | 是不是同一个仓库 |
|---|---|
| `http://localhost:5173` | 一个 |
| `http://127.0.0.1:5173` | 另一个 |
| `http://192.168.x.x:5173`（局域网 IP） | 又一个 |
| `https://qiuyinlan.github.io/duansheli` | 再一个 |

所以在电脑的 localhost 上录的东西，用手机通过局域网 IP 打开**是看不到的**，
反过来也一样。这不是 bug，是浏览器的安全模型。

**局域网 IP 还会变**：换个 WiFi、重连路由之后 IP 可能就不是原来那个了，
而数据仍然锁在旧 IP 那个仓库里（除非那个 IP 又能用起来）。

**设置页底部的「当前网址」**一眼就能看出自己在哪个仓库里。要跨地址用数据，走**导出 / 导入**。

> 这条不写清楚，「换个地址打开」看起来就跟「数据全丢了」一模一样 ——
> 我自己在这件事上就吃过一次惊吓。所以现在空数据时的引导页上也写了这句话。

#### 分不清是哪种情况？跑一次「数据体检」

设置页底部那一块会把当前网址下的**原始事实**读出来给你看：库在不在、
主记录有多少件物品、快照有几份分别是什么时候的、本地偏好有哪几项。
然后给一个结论：

| 结论 | 意思 | 该做什么 |
|---|---|---|
| **数据在** | 一切正常 | 不用管 |
| **很可能能找回来** | 当前物品比快照里最多的一份还少 | 点「回退到物品最多的那一份」 |
| **这个网址下没找到数据** | 这个地址从来没存过东西 | 去别的地址（见上表）各跑一次体检 |
| **读不出来** | 浏览器不给读 / 库损坏 | 换浏览器或看错误信息 |

它会在你打开设置页时自动跑一次 —— 会点进来找数据的人往往已经慌了，
不该再指望他自己发现要点哪个按钮。

> 体检**只读**，不会写任何东西，也不会顺手读 localStorage 里的值
> （那个值里躺着 API Key）。有测试守着这两条。

## AI 助手（可选）

不想一件件敲？也懒得自己归类？**跟 AI 说一句话就行** ——
录新的、改现有的，都是同一句话的事。

```
衣柜里有一件灰色的羊毛衫，还有两条牛仔裤。
床头柜上放着一个旧手机，已经不用了。
厨房的橱柜里有一个平底锅，大概两百块买的。
```

这四种写法它都能懂：

- 写一段文字让它拆成物品
- `把药品改成 药品/补剂`
- `把没分类的那些都归一下类`
- `把闲置超过一年的列出来我看看`

### 怎么用

1. 到 [platform.deepseek.com](https://platform.deepseek.com/api_keys) 创建一个 API Key（建议单独建一个，方便随时吊销）
2. 打开网站的 **AI 助手** 页，把 Key 粘进去（会记住，不用每次填）
3. **直接在对话框里说一句话**，两种都行：
   - **录新的**：`衣柜里有一件灰色羊毛衫，两条牛仔裤` → 它拆成一条条物品
   - **改现有的**：`把药品改成 药品/补剂` → 它自己把你现有的物品找出来改

**没有模式切换，就一个对话框。** 它会自己判断你要干嘛。

改完的东西放在旁边的草稿区里（桌面在右边，手机在下面），每条都能改、能取消勾选，
**点了「采纳」才会写进数据库**。
不满意就继续说 —— 「口红别归日用品」「那两瓶卸妆膏不要了」。

### 它是怎么工作的

```
你：把药品改成 药品/补剂
AI：你「药品」下有 74 件，我先拉进来看看      ← 它自己去调数据
    右侧草稿出现 74 条，带「已有」标记
AI：好，74 件都归到「药品 / 补剂」了
你：再把没分类的那些理一下                   → 继续改
              [ 采纳 · 更新 77 ]  ← 你点了才会写入
```

**草稿里混着两种东西，采纳时自动分流：**

| 草稿条目 | 来源 | 采纳时 |
|---|---|---|
| 带「**已有**」标记 | 从数据库拉进来的 | **更新**那一条 |
| 没有标记 | 这次新录入的 | **创建**一条新的 |

你不用管区别 —— 按钮上会写清「更新 74 · 新建 3」。
没被你改动过的已有物品会**跳过**，不白刷它们的修改时间。

**三条安全底线：**

1. **AI 每轮只返回改动过的条目。** 没有提到的一律**原样保留** ——
   删除必须由 AI 显式声明。所以「没提到」不会误伤，AI 也能正常删东西
2. **改动会被高亮**，你能看出这一轮到底动了哪几条
3. **永远不自动写入。** 只有你点「采纳」才进数据库；
   删掉的已有物品是进**回收站**，可以恢复

### 省 token 的几个设计

每轮都要重发不少东西，所以专门优化过：

| 做法 | 效果 |
|---|---|
| **AI 只返回改动过的条目**（不是每轮吐回整份草稿） | 33 条物品时，每轮输出从 2500+ tokens 降到几十 |
| **用户体系放在 system 消息里** | 请求开头稳定 → 命中 DeepSeek 的**前缀缓存**，便宜很多 |
| **草稿里的空字段不发**（空标签、空属性、空备注） | 一整批能省三成以上输入 |
| **历史只留最近 8 条消息** | 草稿本身就是完整状态，历史留太长纯烧钱 |

界面上会显示「上轮 N · 共 M」tokens，让你看得出这轮贵不贵。

**省钱的用法**：改完一批就点「采纳」，然后点「**新对话**」重新开始 ——
对话越长、草稿越大，每轮要重发的内容也越多。新对话按钮带二次确认，
因为草稿还没入库，关掉就真没了。

### 对话会留到什么时候

**在页面之间来回走不会丢。** 去物品列表、去设置看一眼，再回到 AI 页，
对话和还没采纳的草稿都还在 —— 不用重新让 AI 整理一遍。

**刷新或关掉浏览器就清空了。** 这是刻意的：历史每轮都会进 prompt，
存下来就等于下次打开还在为它付费。想留着的东西就点「采纳」入库。

> 之所以要专门说这一条：早期版本的会话状态存在页面组件里，
> 去别的页面转一圈回来就归零了 —— 聊到一半的对话、AI 已经提取好但
> 还没采纳的草稿，全都白丢。现在状态挪到了一个**内存级**的 store，
> 跨页面活着、但不落盘。有测试盯着这两条边界
> （包括「磁盘上不许出现会话内容」）。

**数据被整体替换时会作废并告诉你。** 清空所有数据、导入覆盖、
回退快照、恢复脚手架这四件事之后，之前的对话和草稿会清掉，
并弹一条说明 —— 因为草稿里的物品、分类、位置都是照着**原来那份数据**
记的，换一份之后就对不上号了，再采纳会悄悄少做几条。
合并导入**不会**清（本地物品都还在，草稿依然有效）。

### 关于 Key 的存放 —— 请读这段

**Key 保存在这台设备的浏览器里**（localStorage 里名为 `duansheli:ai-key` 的键），
所以刷新、关掉重开都还在，不用每次粘贴。页面上有显眼的「清除」按钮，一键删掉。

它**不会**进导出的备份文件，也**不会**进本地数据库（IndexedDB）。
这两条有自动化测试守着（`tests/ai.ts` 的「API Key：存在本地，但不外泄」一组）。

**请求由你的浏览器直连 `api.deepseek.com`，不经过任何第三方服务器。**
这一点是实测验证过的，不是推测：

```bash
node scripts/probe-deepseek-cors.mjs
```

它发一个带 `Origin` 头的预检请求，确认 DeepSeek 会回
`access-control-allow-origin` 和 `access-control-allow-headers: authorization`。
**没有这个前提，纯静态站想调 API 就只能靠代理转发，而那样你的 Key 一定会经过别人的服务器。**

### 存下来意味着什么（请知情）

方便是有代价的。浏览器里存 Key 有两个固有风险，纯前端无法消除：

1. **任何能在你浏览器上执行 JS 的代码理论上都能读到它** —— 恶意浏览器插件、其他页面的 XSS。
2. **更隐蔽的一个**：浏览器的存储按**域名**隔离，而 GitHub Pages 的
   `用户名.github.io` 是**所有仓库共享同一个域名**的。也就是说，如果你将来在同一账号下
   部署了别的项目，那个项目的页面**能读到这个 Key**。

所以建议：

- 到 DeepSeek 开放平台**单独建一个只用于这里的 Key**，方便随时吊销、也方便看用量
- 不想留就点页面上的**「清除」**
- 想手动清：开发者工具 → Application → Local Storage → 删掉 `duansheli:ai-key`

### 费用

**我不在界面里写死价格**，因为官方调过几次，写死的数字迟早会过期骗到你。
每次调用结束后会如实显示这次消耗的 token 数（输入 / 输出分开），
乘一下官网当前的单价就是实际花费。你可以在 DeepSeek 控制台设置余额告警。

### 为什么结果一定先给你看

**AI 一定会认错，也一定会提出你不想要的分类。** 所以：

- 识别结果**绝不直接写入**，一定先出预览
- 每条都能改名、改数量、改备注、取消勾选
- **AI 建议的新分类和新位置默认不勾选**，要你逐个点头才创建 ——
  分类是你精心维护的受控词表，让 AI 随便加，用不了多久就会变成一堆同义词
- AI 提到但属性库里没有的属性会被丢掉，并在界面上如实告诉你

### 长文本会被自动分批

一次塞太多，输出的 JSON 会因为 `max_tokens` 被截断，而**截断的 JSON 是解析不了的** ——
你会以为「AI 认不出来」，其实是结果被砍掉了后半截。

所以程序按段落把长文本切成每批约 2500 字，依次识别并合并结果，
界面上显示「正在识别第 2 / 5 批」和累计 token。某批结果真的被截断时也会明确告诉你。

### 怎么写效果最好

- **一次写一个区域**（一个抽屉、一个柜子），比一次铺开写整间屋子更容易对准位置
- **提到位置时用你已有的叫法**（「衣柜」「床头柜」），AI 会自动对到你的位置树上
- **说清数量**：「两条牛仔裤」比「牛仔裤」更准
- 写得越具体，认出来的越准 —— 但也别指望它凭空补出原文没有的信息

### 它能听懂你说的「状态」和「活动」

它不只是会抽物品名 —— **这个工具里的词它有确切的理解**。你可以直接说：

| 你说 | 它会做的事 |
|---|---|
| 「这个标记为闲置」「这几件不用了」 | 把状态改成 **闲置** |
| 「这两件是备用的」「多买的那些收起来了」 | 把状态改成 **备用** |
| 「这个拿出来用了」 | 把状态改回 **在用** |
| 「加进旅行」「这个出差要带」 | 放进 **活动**「旅行」 |
| 「这个扔了吧」 | 移入**已舍弃回收站**（不是真删，能恢复） |

**「闲置」和「备用」它分得清**，因为这是两个不同的概念：闲置是「该处理了」，
备用是「特意留着的」。它不会再把这两个词塞进标签里。

**活动必须是你已经建过的。** 它不会自己造一个新活动 —— 说了一个你不存在的活动名，
草稿预览里会明确告诉你「你没有这个活动，已忽略」，而不是悄悄建一个出来。
（想用的话，先去「活动」页建一个。）

**关于「清单」**：那是你勾选物品后自己建的一次性待办，AI **没有**权限创建它。
你让它「建个打包清单」，它会在回复里说明该怎么做，同时可以帮你把东西放进某个**活动**。

> 这一条是个真事：早期版本里我说「这个改成闲置」，它**给我打了个「闲置」标签** ——
> 因为它听懂了，但程序里根本没有能装「闲置」的地方，标签是它唯一能塞的槽。
> 现在它有了专门的字段，提示词里也明确写了「状态词不许写进标签」。

### 它是怎么对上你的数据的
调用时会把**你已有的分类清单、完整的位置树路径、属性名、标签、活动名**一并发给 AI，
明确要求它优先复用。

匹配规则里有一条是刻意保守的：

```
AI 说「家 / 车库 / 货架」，你的树里只有「家 / 储物间 / 货架」
        ↓
❌ 不按末级名称「货架」硬凑过去（那会把东西悄悄挪到储物间）
✅ 标成「新位置」，默认不勾，交给你决定
```

只有当 AI 只给了一个名字、没有层级上下文时，才会按名称匹配。
这条规则有专门的测试守着，因为它属于「出错时你根本不会发现」的那类 bug。

## 功能说明

### 录入

- **只有名称是必填的**，其余都可以以后慢慢补
- 位置和分类会**记住上次的选择** —— 整理同一个抽屉时可以一路回车
- `Ctrl / ⌘ + Enter` = 保存并继续录入
- 属性按需勾选；程序还会记住「这个分类上次用了哪些属性」，下次自动带上

### 浏览

物品列表页可以按 **分类 / 位置 / 标签 / 状态 / 有效期** 自由切换分组维度，
排序也多了「按有效期」（**没填日期的一律排在最后**，不会把要紧的冲散）。

**分类和位置是树形分组**：默认只显示一级，点开才看到子分类，子分类还能再点开。
- 有子级的分组默认折叠，**叶子节点直接展开**（它下面没结构可钻，折叠只是白点一次）
- 展开状态会记住，所以只需点一次
- 父级的件数是含子孙的去重合计
- 一件东西都没有的分类不会显示

**每个分组一种颜色**，整组一条彩色竖条；同一个分类的颜色永远不变，
所以你能靠颜色认东西。概览页的条形图用同一套颜色，图表和列表能对上。

筛选支持：搜索（名称、备注、标签、属性值、**分类名、位置名**）、分类、位置（可含子位置）、
状态、标签、**有效期（已过期 / 快到期 / 还早 / 没填）**、属性比较（如「价格 > 100」）。

位置页是左树右列表，点哪个位置就看哪个位置的东西，
每个节点右侧显示数量，空位置用浅灰显示 —— 一眼看出哪里是空的。

### 有效期（过期时间）

给药品、化妆品、食品这类有保质期的东西填上「有效期至」。填过的会汇总到**有效期**页，
分四档：

| 档位 | 含义 | 界面表现 |
|---|---|---|
| **已过期** | 日期已经过了 | 红色实心徽章 —— 全站唯一一处「重」提示 |
| **快到期** | 还有 N 天以内（**N 可调**，默认 30） | 琥珀色徽章 |
| **还早** | 还远着呢 | 灰色小字 |
| **没填** | 没设置 | **什么都不显示** |

最后一条是刻意的：如果给「没填」也画个灰色标签，一屏看过去全是标签，
真正要紧的那几条反而被淹掉了。

**「快到期」算多少天是可以调的** —— 鲜奶是 3 天，化妆品是半年，
写死一个数必然对一半人没用。在有效期页顶部选，选完记在这台设备上。

**到期不会自动改动你的任何数据。** 不会自动标闲置、不会自动进回收站、不会改状态。
过期只是个**算出来的状态**，每次渲染现算。理由很实在：如果到期就自动标闲置，
等你哪天觉得某个东西还能用，数据已经被悄悄动过了 ——
这和整个项目「只有你点了才写入」的原则冲突。

日期只存到天（`2026-03-15`），不存时间点。因为保质期是日历概念：
带上时分秒之后，「今天到期」过了零点就会变成「已过期 1 天」，很别扭。

### 活动合集

一件东西归在哪儿（位置）和它是什么（分类）是两回事，还有第三个问题：
**「为了做这件事，我得凑齐哪些东西」** —— 出发前一晚对着手机核对，看有没有漏带。

所以有「活动」：旅行、学习、搬家，各自是一份清单。

- **建活动**：活动页右上角「新建活动」，或者加东西的时候顺手输一个新名字
- **放东西进去**：在物品列表里勾选几件 → 点「**加入活动**」→ 选一个已有活动（或新建一个）
- **一件东西可以同时属于多个活动**：充电宝既在「旅行」也在「出差」，这很正常
- **删活动不删东西**：删掉「旅行」只是解除关联，你为了旅行准备的那些东西**一件都不会少**。
  界面上会如实告诉你影响了多少件，删除前的确认框里也写明了这一点

**活动为什么不用标签代替**：标签回答的是「这件东西对我意味着什么」（想送人、舍不得扔），
一件东西身上挂几个都很自然；活动回答的是「为了这件事要凑齐什么」，它自己是一个
可以浏览、可以核对的整体。混在一起的话，「旅行」会和「想送人」并排出现在标签筛选里，
两个完全不同性质的维度被压成一层。

**首次启动不会预置任何活动**。分类和位置能预置，是因为「家里有哪些房间、东西分几类」
几乎共通；但活动完全因人而异 —— 给不旅行的人塞一个「旅行」只是噪音。
（`示例数据-导入用.json` 里倒是给了「旅行 / 学习 / 搬家」三个，那是演示用的。）

### 清单

活动和清单是**模板**和**这次的实例**的关系：

| | 活动合集 | 清单 |
|---|---|---|
| 是什么 | 攒起来的模板 | 这一次的待办 |
| 例子 | 「旅行」= 出门要带的东西 | 「周末露营」= 这次真带哪些 |
| 能打钩吗 | 不能 | **能**，边办边打 |
| 删了心疼吗 | 会（那是你慢慢攒的） | 不会，本来就是临时的 |

**两种建法**：

1. **从活动**：进「旅行」→ 勾选这次要带的那几件 → 「生成清单」
2. **从物品**：在物品列表里勾选几件 → 选中栏「新建清单」

**清单里能做的**：

- **打钩 / 取消** —— 一步完成，打钩的整行会淡下去并划掉
- **就地改名和改数量** —— 名字和数量平时看着就是文字，点进去就能改。
  ⚠️ 这里改的是**清单上的这一条**，不会去动库里的物品
  （「充电宝」写成「充电宝（借的）」不该把物品也改了名）
- **加一条库里没有的** —— 比如「顺路买瓶水」。清单不要求每条都对应一件物品
- **清掉已打钩的** —— 办完的划掉，剩下的继续在眼前
- **删掉整份清单** —— 临时东西，不留痕迹

**条目是快照**：名字和数量在生成时就抄下来了。所以物品后来改名、改数量、甚至被删掉，
这份清单都还是当时那个样子 —— 它记录的本来就是「当时决定要带什么」。
物品被删掉的那条会标一个「已不在库里」，但不会消失。

### 中英双语

右上角一个开关，中英随时切。**不用刷新页面**，整页立刻变。

**翻译的边界**：

| 层 | 例子 | 处理 |
|---|---|---|
| 界面文案 | 「概览」「还没有物品」 | 翻译 |
| **你录入的内容** | 你建的分类「化妆品」、位置「家 / 卧室」、物品名 | **绝不翻译**，永远原样 |
| AI 提示词 | 发给 DeepSeek 的那套规则 | 两份（中 / 英），跟着界面语言走 |

第二条是硬性边界，有测试守着。第三条里还额外加了一条规则：
**不许 AI 翻译你的分类名** —— 否则你一开口说英文，它会把「衣物」输出成「Clothing」，
把你的数据劈成两半。

**首次启动的脚手架**（家 / 卧室 / 衣柜、衣物 / 电子…）按**当时的界面语言**生成一次。
之后切语言不会去改已有数据 —— 你花时间改过的分类名被悄悄翻译掉，是最恼人的一类 bug。

语言偏好存在浏览器里（`duansheli:lang`），不跟着备份走 ——
换设备、换人的时候，界面语言该跟着人走，而不是跟着数据走。

### 断舍离

```
在用 ──标记闲置──> 闲置 ──已处理──> 已舍弃（回收站，可恢复）
  ↕
备用 ──────────────舍弃──────────────> 已舍弃（回收站，可恢复）
```

「闲置」是独立的一级入口。闲置页**按闲置时长倒序排列**，
闲置最久的排最前面，并显示「已闲置 217 天」这样的提示 ——
不需要你做判断，该处理的东西自己会浮上来。

**设置 → 显示偏好 → 「物品列表里默认不显示闲置的东西」默认是开的**，
它们从日常清单里收起来，顶上会有一条提示告诉你藏了几件、去哪看。
你主动在筛选里点「状态 → 闲置」时**不会**藏（点了就是想看）。

> **提示条为什么不能省**：悄悄藏数据是最糟的结果。没有它，你迟早会遇到
> 「我明明录过那个，怎么不见了」，然后开始怀疑数据丢了。
> 藏了多少、去哪看，必须一眼看得到。

### 备用（多买的那些东西）

买东西难免多买几件：牙膏一买三管、数据线一买三条。
**多出来的那些收进「备用」页**，等用完了再去取。

```
备用 ──取用一件──> 从备用区出来，进入使用
```

**它和「闲置」是两回事，所以是两个栏目。** 闲置页是在提醒你「这些东西该处理了」，
而备用是你**特意留着**的 —— 放两年也完全正常，没人会催你。合在一起的话，
闲置页会跑去劝你扔掉自己特意囤的东西。

#### 一个东西买多了，怎么录

> 在「物品」页选中它 → 点「**拆出备用**」→ 填几件 → 确认。

比如「牙膏 ×3」，拆出 2 件，就会：
- 原来那条变成 **牙膏 ×1**，留在原地（位置、分类、标签全不动）
- 新建一条 **牙膏（备用）×2**，放进备用区

**原处一定留住 1 件** —— 全拆走就成了「整条都是备用」，
那是「标记备用」那个按钮的事。二次确认里也写了这条。

拆出来的那条和你原来那条**一模一样**（名字、分类、标签、属性、备注、有效期），
只有状态、数量、位置不同 —— 所以备注也会照抄，觉得不对直接改就行。

**位置会记住。** 第一次选好「备用箱」放哪，以后每次拆都自动填上 ——
备用一般就是收在同一个盒子里的。

#### 取用

备用页每条都有「**取用一件**」，含义严格一致：**刚好一件**从备用区出来、进入使用。

| 这条备用 | 取用一件之后 |
|---|---|
| ×1 | 整条变成「**在用**」 |
| ×3 | 变成 ×2，剩下的还留在备用区 |

**取用不会把东西送进回收站** —— 那是「东西被用掉了」，不是扔掉。
回收站只装你主动点「舍弃」的东西。

#### 其它

- **备用页按位置分组**，所以页面上长成「药箱 3 种 / 7 件」这样，和真实的柜子对得上
- 两个数字都会显示：**几种**（囤了几样）和**共几件**（盒子里到底多少）
- **设置 → 显示偏好**里，「不显示备用」是**独立的一个开关**，
  和「不显示闲置」互不影响
- 侧栏「备用」旁边的小数字是**件数**（还剩 7 件），因为囤东西的人关心的是这个
- 录入/编辑页的「状态」是**三选一**：在用 / 闲置 / 备用。
  「已舍弃」不在里面 —— 它是出口，不是随手可选的档位

### 导出

| 格式 | 用途 | 能否恢复数据 |
|---|---|---|
| **JSON** | 完整备份、跨设备迁移 | ✅ 能，这是唯一能完整恢复的格式 |
| **CSV** | 用 Excel 打开查看、打印清点 | ❌ 不能，有损格式 |

CSV 带 BOM，Excel 打开中文不会乱码。

## 开发

### 技术栈

Vite 5 · React 18 · TypeScript · react-router-dom（HashRouter）· zustand · 原生 CSS

运行时依赖只有 **4 个**。图表是自己用 div 画的，图标是自己写的 SVG，
UI 组件全部手写 —— 因为「极简无彩色」的风格自己写反而代码更少、控制力更强。

### 数据存储

整个数据集是一个纯 JSON 对象，**整体读写**，不做表结构：

```
导出 = JSON.stringify(data)        零转换成本
导入 = 校验 + 写入                  零转换成本
快照 = 存一份副本                   零转换成本
换后端 = 只替换 load() / save()    业务代码零改动
```

数据量很小（250 件物品约 60KB），整体读写让上面四件事都变得极其简单。
存储层已经抽象成 `Repository` 接口 —— 将来接 Supabase 做账号和云端同步时，
只需要新增一个 `SupabaseRepository` 实现，业务代码一行不用改。

### 测试

```bash
npm test            # 408 项
npm run audit:i18n  # 漏翻的中文与词典对齐
npm run check       # 类型检查 + 上面两样，提交前跑这个
```

用 `fake-indexeddb` 在 Node 里模拟浏览器存储，用 `jsdom` 真实挂载 React 组件，
所以跑的是**真实的持久化链路和真实的渲染通路**。

覆盖范围：

- **导出 → 导入 往返后逐字段一致**（这是硬指标，不通过就不算完成）
- 损坏文件 / 非本程序文件 / 更高版本数据被明确拒绝
- 合并算法：id 去重、`updatedAt` 较新者胜、悬空位置按名称路径对齐、缺失位置自动补建
- 位置树：无孤儿无环、防「移动到自己的子孙下」
- 筛选、分组、统计的正确性
- IndexedDB 存取、快照的分钟级节流与 30 份上限
- store 端到端：录入 → 落盘 → 导出 → 清空 → 从快照回退
- **有效期**：日期归一（含斜杠/中文/纯数字写法）、**时区不把日子挪走一天**、
  `2025-02-30` 这种「格式对但不存在」要拒绝、四档状态的边界、阈值可调、
  **只为改有效期也必须有改动**（否则用户的修改会被静默跳过）、
  只设日期**不动 status**、导出导入往返、老备份缺字段补 null
- **活动合集**：同名不重复建、重复添加被挡掉、一件东西可属多个活动、
  **删活动一件物品都不能少**（这是最危险的一条）、空名字与重名改名被拒绝、
  按活动取物品时不含已舍弃的、导出导入往返、老备份缺字段补空、
  悬空活动引用被清掉并提示、合并导入时本地改过的名字保留
- **AI 回复解析**：代码围栏、前言后语、中文键名、字符串数量、缺字段 —— 全部要能降级而不是崩掉
- **AI 名称匹配**：分类与位置的完整路径匹配、后缀唯一匹配、危险的同名跨分支必须**不**匹配
- **AI 对话改数据**：id 命中就更新、**没提到的一律保留且保持原顺序**、removedIds 才删、用户勾选不被 AI 改掉
- **AI 采纳分流**：拉进来的改「更新」、新录入的走「创建」、已有物品没改动则**跳过**不刷 `updatedAt`
- **AI 按需取数**：只说 `loadScope` 不吐数据就自动再问一轮，且轮数有上限不会失控
- **省 token 的三条设计**：空字段不发、上下文放 system 消息（前缀缓存）、历史有条数上限
- **分类多级**：路径逐层创建、同一路径只建一次、已有路径复用、两个「眼妆」时必须判为歧义
- **Prompt 约束防回归**：「原文写了归类名就必须用它」「宁可新建也不要硬塞」这类指令必须真的在 prompt 里
- **API Key 边界**：存本地但绝不进导出文件、绝不进 IndexedDB、全站只有一处存着它
- **板块配色**：每条路由都能拿到主色、十个板块不撞色、未知路由回落默认色
- **分组配色**：同 key 同色可重复、**相邻分组绝不撞色**、虚拟分组中性灰、状态走语义色
- **双语**：两份词典 key 与插值占位符**逐条对齐**、单复数成对出现、
  **切语言后各处文字真的会变**（专抓「冻在模块加载那一刻」那类 bug）、
  种子脚手架按语言生成、**用户录入的内容不被翻译**
- **每个页面在真实 DOM 里挂载一遍**，覆盖空数据、悬空引用、300 件数据等边界情况；
  并且在**英文下把 15 个页面各挂一遍**，漏订阅语言的组件会在这里露出来

测试不覆盖网络请求本身 —— 那是在测 DeepSeek，不是测这个项目。
API 客户端只测错误映射与响应解析，真实调用请用 `scripts/probe-deepseek-cors.mjs` 验证连通性。

### 已知限制

1. **手机和电脑数据不互通**（v1），靠手动导出 / 导入。计划用 Supabase 解决。
2. **不支持照片** —— 这是刻意的取舍，换来更快的录入和更干净的界面。
   建议名称写具体一点（写「灰色羊毛衫」而不是「毛衣」）。
3. **CSV 只能导出不能导入**（信息有损）。
4. **合并导入可能产生重复项** —— 按 id 去重，两台设备分别录入的同一件东西会出现两条，需要手动删一条。
5. **AI 功能需要你自己的 DeepSeek API Key，并按用量付费**。它只负责「提出建议」，
   最终判断必须由你过一遍预览 —— 这部分刻意不做自动化。
6. **使用 AI 功能时，你粘贴的文字会发送到 DeepSeek 的服务器。**
   这是该功能的必然代价，无法在保持「不经过第三方」的前提下避免。
   不想发送就不要用 AI 功能，手写录入完全不受影响。
7. **有效期只是一天一天的日期，没有「循环提醒」**（比如每三个月换一次滤芯）。
   也不会到期自动帮你做任何事 —— 见上面「有效期」那节的说明。
8. **活动没有「已备齐」的勾选状态**。它是「这件事要用哪些东西」的清单，
   不是出发前的打勾表。想做打勾表的话告诉我，那要另存一份「本次带了没」的状态。
9. **英文版是完整的界面翻译，但文档（README / 设计文档）只有中文**。
   另外品牌名「断舍离」在英文界面里也保持原样，它是个名字，不是一句要翻的话。
