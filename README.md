# 断舍离 · 个人物品整理

> 录入你的所有物品，给它们指定位置，按分类随时回看。
> 目标只有一个：**让你看清自己到底有多少东西，然后扔掉该扔的。**

电脑和手机都能用，每个板块有自己的主色，数据只存在你自己的设备上。

## 怎么跑起来

需要 **Node 18 或更高版本**（推荐 20+）。

```bash
npm install     # 安装依赖
npm run dev     # 启动开发服务器，打开提示的地址即可
```

其他命令：

```bash
npm run build      # 类型检查 + 打包到 dist/
npm run preview    # 本地预览打包结果
npm test           # 运行测试（176 项）
npm run typecheck  # 只做类型检查
npm run icons      # 重新生成 PWA 图标
```

还附带一个诊断脚本，用来确认 DeepSeek 是否仍允许浏览器直连（AI 功能的安全前提）：

```bash
node scripts/probe-deepseek-cors.mjs
```

首次打开时，程序会给你铺一套**起步脚手架**：常用的 10 个分类、一套居家位置树
（家 › 卧室 › 衣柜…）、5 个属性定义、3 个常用标签。**不会塞任何示例物品**，
物品列表从空开始。这些脚手架都可以随意改名或删除。

## 部署到 GitHub Pages

推送代码就会自动部署，全程免费。

### 一次性配置

1. 在 GitHub 上新建一个仓库（**Public** 或 Private 都行，Pages 对公共仓库免费），
   不要勾选 "Add a README"。
2. 在项目目录里把代码推上去：

   ```bash
   git init
   git add .
   git commit -m "断舍离 v1"
   git branch -M main
   git remote add origin https://github.com/你的用户名/你的仓库名.git
   git push -u origin main
   ```

3. 打开仓库的 **Settings → Pages**，把 **Source** 改成 **GitHub Actions**。
4. 回到 **Actions** 标签页，等待「部署到 GitHub Pages」跑完（约 1～2 分钟）。

### 访问地址

```
https://你的用户名.github.io/你的仓库名/
```

手机浏览器打开这个地址后，可以「添加到主屏幕」，之后就像 App 一样打开，还能离线使用。

> 部署配置里已经用了相对路径（`base: './'`）和 Hash 路由，
> 所以**仓库名随便叫什么都能跑**，刷新页面也不会 404。

## 数据安全（请务必读这一段）

这一版是**纯本地**的：数据存在你自己浏览器的 IndexedDB 里，**不会上传到任何服务器**。
私密、免费、不依赖网络，但也带来三个必须知道的事实。

### 1. 手机和电脑是两份独立数据，不会自动同步

GitHub Pages 只是把网页文件发给你，它不存你的数据。
在电脑上打开，数据落在电脑浏览器里；在手机上打开，数据落在手机浏览器里，两边互相看不见。

要搬家就用导出 / 导入：

```
手机：设置 → 导出 JSON → 通过微信 / 网盘 / 邮件传到电脑
电脑：设置 → 导入备份 → 选择「覆盖」 → 完成
```

想把两边各自录的东西合起来，导入时选「**合并**」——位置会按名称路径自动对齐，
缺失的会自动补建，导入结束后会给你一份详细报告。

### 2. 浏览器数据可能被清掉

清理浏览器数据、换浏览器、无痕模式、iOS 长期不访问都可能让数据消失。
**所以请定期导出 JSON 备份**，存到网盘或电脑里。

程序里做了三层保护：

| 机制 | 作用 |
|---|---|
| **自动快照** | 每次修改前自动存一份（同一分钟只留一份），最多 30 份；导入前、删除位置/分类/属性前的快照额外保底保留 |
| **一键导出** | 设置页导出完整 JSON；超过 7 天没导出，概览页会温和提醒 |
| **导入前自动备份** | 导入永远可回退；回退前又会再存一份，所以**回退本身也能回退** |
| **已舍弃回收站** | 扔掉的东西不真删，留在回收站里可以回顾也能恢复 |

### 3. 换域名会让旧数据「看不见」

浏览器的存储按域名隔离。如果你以后给 GitHub Pages 绑了自定义域名，
域名一变，旧域名下的数据就不会跟过来（数据还在，只是换了把钥匙）。

**绑定自定义域名之前，务必先导出 JSON。**

## AI 批量录入（可选）

不想一件件敲？把一段文字交给 DeepSeek，它帮你拆成一条条物品，还会自动对上你已有的分类和位置。

```
衣柜里有一件灰色的羊毛衫，还有两条牛仔裤。
床头柜上放着一个旧手机，已经不用了。
厨房的橱柜里有一个平底锅，大概两百块买的。
```

写进「对话整理」，它会变成 4 条带分类、带位置、带数量的物品，等你确认。

### 怎么用

1. 到 [platform.deepseek.com](https://platform.deepseek.com/api_keys) 创建一个 API Key（建议单独建一个，方便随时吊销）
2. 打开网站的 **AI 助手** 页，把 Key 粘进去（会记住，不用每次填）
3. 在**对话整理**里写下要录的东西，AI 会拆成一条条物品放到右边
4. 哪条不对就**直接用大白话跟它说**：「口红别归日用品，单独建个化妆品」

三个模式：

| 模式 | 适合什么 |
|---|---|
| **对话整理**（默认） | 边聊边改。草稿跨轮次保留，每轮告诉你改了哪几条，可以只采纳一部分 |
| **一次性录入** | 就一段文字，一次识别完事，不想啰嗦 |
| **整理已有物品** | 选一批已录入的物品（比如「未分类的」），让 AI 提出更合理的归类 |

### 对话整理是怎么工作的

```
你：化妆品那批单独成类，别塞日用品
AI：好的，2 件卸妆归到「化妆品 › 护肤」，口红唇釉归「化妆品 › 唇妆」
      右侧草稿实时更新 —— 加粗的是这一轮改过的
你：眼影盘也归眼妆        → 继续改
你：那两瓶卸妆膏不要了     → 删掉
              [ 采纳选中的 12 条 ]  ← 你点了才会写入
```

**三条安全底线：**

1. **AI 每轮只返回改动过的条目。** 没有提到的一律**原样保留** ——
   删除必须由 AI 显式声明。所以「没提到」不会误伤，AI 也能正常删东西
2. **改动会被高亮**，你能看出这一轮到底动了哪几条
3. **永远不自动写入。** 只有你点「采纳」才会进数据库

### 省 token 的几个设计

对话模式每轮都要重发不少东西，所以专门优化过：

| 做法 | 效果 |
|---|---|
| **AI 只返回改动过的条目**（不是每轮吐回整份草稿） | 33 条物品时，每轮输出从 2500+ tokens 降到几十 |
| **用户体系放在 system 消息里** | 请求开头稳定 → 命中 DeepSeek 的**前缀缓存**，便宜很多 |
| **草稿里的空字段不发**（空标签、空属性、空备注） | 一整批能省三成以上输入 |
| **历史只留最近 8 条消息** | 草稿本身就是完整状态，历史留太长纯烧钱 |

界面上会显示「**上轮 N · 共 M** tokens，让你看得出这轮贵不贵。

**省钱的用法**：改完一批就点「采纳」，然后点「**新对话**」重新开始 ——
对话越长、草稿越大，每轮要重发的内容也越多。新对话按钮带二次确认，
因为草稿还没入库，关掉就真没了。

### 关于 Key 的存放 —— 请读这段

**Key 保存在这台设备的浏览器里**（localStorage 里名为 `duansheli:ai-key` 的键），
所以刷新、关掉重开都还在，不用每次粘贴。页面上有显眼的「清除」按钮，一键删掉。

它**不会**进导出的备份文件，也**不会**进本地数据库（IndexedDB）。
这两条有自动化测试守着（`tests/ai.ts` 的「API Key：存在本地，但不外泄」一组）。

**请求由你的浏览器直连 `api.deepseek.com`，不经过任何第三方服务器。**
这一点是实测验证过的，不是推测：

```bash
node scripts/probe-deepseek-cors.mjs
```

它发一个带 `Origin` 头的预检请求，确认 DeepSeek 会回
`access-control-allow-origin` 和 `access-control-allow-headers: authorization`。
**没有这个前提，纯静态站想调 API 就只能靠代理转发，而那样你的 Key 一定会经过别人的服务器。**

### 存下来意味着什么（请知情）

方便是有代价的。浏览器里存 Key 有两个固有风险，纯前端无法消除：

1. **任何能在你浏览器上执行 JS 的代码理论上都能读到它** —— 恶意浏览器插件、其他页面的 XSS。
2. **更隐蔽的一个**：浏览器的存储按**域名**隔离，而 GitHub Pages 的
   `用户名.github.io` 是**所有仓库共享同一个域名**的。也就是说，如果你将来在同一账号下
   部署了别的项目，那个项目的页面**能读到这个 Key**。

所以建议：

- 到 DeepSeek 开放平台**单独建一个只用于这里的 Key**，方便随时吊销、也方便看用量
- 不想留就点页面上的**「清除」**
- 想手动清：开发者工具 → Application → Local Storage → 删掉 `duansheli:ai-key`

### 费用

**我不在界面里写死价格**，因为官方调过几次，写死的数字迟早会过期骗到你。
每次调用结束后会如实显示这次消耗的 token 数（输入 / 输出分开），
乘一下官网当前的单价就是实际花费。你可以在 DeepSeek 控制台设置余额告警。

### 为什么结果一定先给你看

**AI 一定会认错，也一定会提出你不想要的分类。** 所以：

- 识别结果**绝不直接写入**，一定先出预览
- 每条都能改名、改数量、改备注、取消勾选
- **AI 建议的新分类和新位置默认不勾选**，要你逐个点头才创建 ——
  分类是你精心维护的受控词表，让 AI 随便加，用不了多久就会变成一堆同义词
- AI 提到但属性库里没有的属性会被丢掉，并在界面上如实告诉你

### 长文本会被自动分批

一次塞太多，输出的 JSON 会因为 `max_tokens` 被截断，而**截断的 JSON 是解析不了的** ——
你会以为「AI 认不出来」，其实是结果被砍掉了后半截。

所以程序按段落把长文本切成每批约 2500 字，依次识别并合并结果，
界面上显示「正在识别第 2 / 5 批」和累计 token。某批结果真的被截断时也会明确告诉你。

### 怎么写效果最好

- **一次写一个区域**（一个抽屉、一个柜子），比一次铺开写整间屋子更容易对准位置
- **提到位置时用你已有的叫法**（「衣柜」「床头柜」），AI 会自动对到你的位置树上
- **说清数量**：「两条牛仔裤」比「牛仔裤」更准
- 写得越具体，认出来的越准 —— 但也别指望它凭空补出原文没有的信息

### 它是怎么对上你的数据的

调用时会把**你已有的分类清单、完整的位置树路径、属性名**一并发给 AI，明确要求它优先复用。

匹配规则里有一条是刻意保守的：

```
AI 说「家 / 车库 / 货架」，你的树里只有「家 / 储物间 / 货架」
        ↓
❌ 不按末级名称「货架」硬凑过去（那会把东西悄悄挪到储物间）
✅ 标成「新位置」，默认不勾，交给你决定
```

只有当 AI 只给了一个名字、没有层级上下文时，才会按名称匹配。
这条规则有专门的测试守着，因为它属于「出错时你根本不会发现」的那类 bug。

## 功能说明

### 录入

- **只有名称是必填的**，其余都可以以后慢慢补
- 位置和分类会**记住上次的选择** —— 整理同一个抽屉时可以一路回车
- `Ctrl / ⌘ + Enter` = 保存并继续录入
- 属性按需勾选；程序还会记住「这个分类上次用了哪些属性」，下次自动带上

### 浏览

物品列表页可以按 **分类 / 位置 / 标签 / 状态** 自由切换分组维度。

**分类和位置是树形分组**：默认只显示一级，点开才看到子分类，子分类还能再点开。
- 有子级的分组默认折叠，**叶子节点直接展开**（它下面没结构可钻，折叠只是白点一次）
- 展开状态会记住，所以只需点一次
- 父级的件数是含子孙的去重合计
- 一件东西都没有的分类不会显示

**每个分组一种颜色**，整组一条彩色竖条；同一个分类的颜色永远不变，
所以你能靠颜色认东西。概览页的条形图用同一套颜色，图表和列表能对上。

筛选支持：搜索（名称、备注、标签、属性值、**分类名、位置名**）、分类、位置（可含子位置）、
状态、标签、属性比较（如「价格 > 100」）。

位置页是左树右列表，点哪个位置就看哪个位置的东西，
每个节点右侧显示数量，空位置用浅灰显示 —— 一眼看出哪里是空的。

### 断舍离

```
在用 ──标记闲置──> 闲置 ──已处理──> 已舍弃（回收站，可恢复）
```

「闲置」是独立的一级入口。闲置页**按闲置时长倒序排列**，
闲置最久的排最前面，并显示「已闲置 217 天」这样的提示 ——
不需要你做判断，该处理的东西自己会浮上来。

### 导出

| 格式 | 用途 | 能否恢复数据 |
|---|---|---|
| **JSON** | 完整备份、跨设备迁移 | ✅ 能，这是唯一能完整恢复的格式 |
| **CSV** | 用 Excel 打开查看、打印清点 | ❌ 不能，有损格式 |

CSV 带 BOM，Excel 打开中文不会乱码。

## 开发

### 技术栈

Vite 5 · React 18 · TypeScript · react-router-dom（HashRouter）· zustand · 原生 CSS

运行时依赖只有 **4 个**。图表是自己用 div 画的，图标是自己写的 SVG，
UI 组件全部手写 —— 因为「极简无彩色」的风格自己写反而代码更少、控制力更强。

### 数据存储

整个数据集是一个纯 JSON 对象，**整体读写**，不做表结构：

```
导出 = JSON.stringify(data)        零转换成本
导入 = 校验 + 写入                  零转换成本
快照 = 存一份副本                   零转换成本
换后端 = 只替换 load() / save()    业务代码零改动
```

数据量很小（250 件物品约 60KB），整体读写让上面四件事都变得极其简单。
存储层已经抽象成 `Repository` 接口 —— 将来接 Supabase 做账号和云端同步时，
只需要新增一个 `SupabaseRepository` 实现，业务代码一行不用改。

### 测试

```bash
npm test
```

用 `fake-indexeddb` 在 Node 里模拟浏览器存储，用 `jsdom` 真实挂载 React 组件，
所以跑的是**真实的持久化链路和真实的渲染通路**。

覆盖范围：

- **导出 → 导入 往返后逐字段一致**（这是硬指标，不通过就不算完成）
- 损坏文件 / 非本程序文件 / 更高版本数据被明确拒绝
- 合并算法：id 去重、`updatedAt` 较新者胜、悬空位置按名称路径对齐、缺失位置自动补建
- 位置树：无孤儿无环、防「移动到自己的子孙下」
- 筛选、分组、统计的正确性
- IndexedDB 存取、快照的分钟级节流与 30 份上限
- store 端到端：录入 → 落盘 → 导出 → 清空 → 从快照回退
- **AI 回复解析**：代码围栏、前言后语、中文键名、字符串数量、缺字段 —— 全部要能降级而不是崩掉
- **AI 名称匹配**：分类与位置的完整路径匹配、后缀唯一匹配、危险的同名跨分支必须**不**匹配
- **AI 对话整理**：id 命中就更新、**没提到的一律保留且保持原顺序**、removedIds 才删、用户勾选不被 AI 改掉
- **省 token 的三条设计**：空字段不发、上下文放 system 消息（前缀缓存）、历史有条数上限
- **分类多级**：路径逐层创建、同一路径只建一次、已有路径复用、两个「眼妆」时必须判为歧义
- **Prompt 约束防回归**：「原文写了归类名就必须用它」「宁可新建也不要硬塞」这类指令必须真的在 prompt 里
- **API Key 边界**：存本地但绝不进导出文件、绝不进 IndexedDB、全站只有一处存着它
- **板块配色**：每条路由都能拿到主色、九个板块不撞色、未知路由回落默认色
- **分组配色**：同 key 同色可重复、**相邻分组绝不撞色**、虚拟分组中性灰、状态走语义色
- **每个页面在真实 DOM 里挂载一遍**，覆盖空数据、悬空引用、300 件数据等边界情况

测试不覆盖网络请求本身 —— 那是在测 DeepSeek，不是测这个项目。
API 客户端只测错误映射与响应解析，真实调用请用 `scripts/probe-deepseek-cors.mjs` 验证连通性。

### 已知限制

1. **手机和电脑数据不互通**（v1），靠手动导出 / 导入。计划用 Supabase 解决。
2. **不支持照片** —— 这是刻意的取舍，换来更快的录入和更干净的界面。
   建议名称写具体一点（写「灰色羊毛衫」而不是「毛衣」）。
3. **CSV 只能导出不能导入**（信息有损）。
4. **合并导入可能产生重复项** —— 按 id 去重，两台设备分别录入的同一件东西会出现两条，需要手动删一条。
5. **AI 功能需要你自己的 DeepSeek API Key，并按用量付费**。它只负责「提出建议」，
   最终判断必须由你过一遍预览 —— 这部分刻意不做自动化。
6. **使用 AI 功能时，你粘贴的文字会发送到 DeepSeek 的服务器。**
   这是该功能的必然代价，无法在保持「不经过第三方」的前提下避免。
   不想发送就不要用 AI 功能，手写录入完全不受影响。
